# 미소 습관 중심 제품 전환 설계

- 날짜: 2026-07-27
- 상태: 승인됨
- 배경: SmileDay의 핵심 가치는 얼굴이나 미소 크기의 개선을 평가하는 데 있지 않다. 사용자가 하루 중 잠시 멈춰 의식적으로 미소 짓고, 자신을 웃게 한 좋은 순간을 떠올리며, 그 행동을 부담 없이 반복하도록 돕는 것이 제품의 목적이다. 현재 앱은 AR 측정 점수, 전날 대비 상승, 좌우 차이와 얼굴 긴장 분석을 전면에 노출해 이 목적과 어긋난다.

## 1. 제품 정의

SmileDay는 얼굴 개선 앱이 아니라 **미소 습관과 긍정적인 회고를 돕는 온디바이스 기록 앱**이다.

핵심 루프:

```text
알림 또는 자발적 진입
→ 짧은 질문을 읽음
→ 잠시 미소 지음
→ 지금의 기분과 좋은 순간을 선택적으로 기록
→ 웃어본 날과 순간이 쌓임
→ 다음 미소 시간을 자연스럽게 이어감
```

ARKit은 미소를 평가하는 심사 도구가 아니라 사용자가 실제로 얼굴을 비추고 잠시 미소 짓도록 돕는 상호작용 장치다. 측정 수치는 촬영 가능 여부, 조명·각도 안내, 기존 데이터 호환을 위해 내부에 유지하지만 기본 사용자 경험에서 성과나 우열로 표시하지 않는다.

## 2. 제품 원칙

1. **행동을 기록하고 얼굴을 평가하지 않는다.**
   - “얼마나 크게 웃었는가”보다 “오늘 잠시 웃어보았는가”를 보여준다.
   - 점수 상승·하락, 좌우 우열, 진짜/억지 미소 판정을 기본 화면과 알림에서 제거한다.

2. **좋은 마음을 강요하지 않는다.**
   - 힘든 날에도 체크인할 수 있어야 한다.
   - 기록이 끊겨도 실패, 손실, 초기화 같은 표현을 쓰지 않는다.
   - “긍정적으로 생각하세요” 대신 “잠시 숨을 고르고 떠오르는 순간이 있으면 적어보세요”처럼 선택권을 준다.

3. **회고는 선택 사항이다.**
   - 기분과 한 줄 기록을 입력하지 않아도 미소 시간은 정상 완료된다.
   - 빈 기록을 부정적으로 표시하지 않는다.

4. **무료 핵심 루프를 완결한다.**
   - 매일 미소 짓기, 기본 질문, 기분 선택, 한 줄 기록, 최근 7일 습관은 무료다.
   - Pro는 핵심 행동을 막지 않고 개인화·장기 회고·다중 리마인더를 확장한다.

5. **온디바이스 원칙을 유지한다.**
   - 얼굴 이미지·영상은 저장하지 않는다.
   - 질문, 기분, 한 줄 기록도 SwiftData에 로컬 저장한다.

## 3. 사용자 언어

### 권장 용어

| 기존 | 변경 |
|---|---|
| 코칭 | 미소 시간 |
| 케어 | 쉬어가기 |
| 측정 | 미소 짓기 / 미소 시간 |
| 점수·미소 크기 | 완료 여부 / 웃어본 순간 |
| 인사이트 | 오늘의 한마디 / 돌아보기 |
| 개선·상승 | 이어감 / 쌓임 / 다시 시작 |

### 금지하거나 기본 UI에서 제거할 표현

- 점수가 올랐어요 / 내려갔어요
- 더 크게 웃어야 해요
- 왼쪽·오른쪽이 약해요
- 진짜 미소 / 억지 미소
- 표정을 교정해요
- 미소가 개선됐어요
- 연속 기록이 깨졌어요

### 기본 문구 예시

- “오늘도 잠시 웃어보는 시간을 가져볼까요?”
- “잘 웃었는지 평가하지 않아요. 잠시 미소 지은 오늘을 기록해요.”
- “오늘 나를 미소 짓게 한 순간이 있었나요?”
- “떠오르는 순간이 없다면 비워두어도 괜찮아요.”
- “쉬어간 날이 있어도 오늘 다시 시작하면 돼요.”

## 4. 데이터 설계

새 SwiftData 모델을 추가하지 않고 기존 `CheckInSession`에 선택적 필드를 추가한다. 기존 레코드와 경량 마이그레이션 호환을 유지하기 위해 모두 optional + nil 기본값으로 둔다.

```swift
@Model
public final class CheckInSession {
    // 기존 필드 유지
    public var promptText: String? = nil
    public var smileMomentNote: String? = nil
}
```

- `promptText`: 해당 미소 시간을 시작하게 한 질문. 일반 진입에서 질문이 없으면 nil.
- `smileMomentNote`: “오늘 나를 미소 짓게 한 순간”에 대한 선택적 한 줄 기록.
- 기존 `mood`: 현재 기분 선택에 계속 사용.
- `scoreDelta`와 얼굴 측정 통계: 저장 호환, 측정 품질, 향후 명시적 고급 기능을 위해 유지하되 기본 UI에서는 숨김.
- 한 줄 기록은 앞뒤 공백을 제거하고 최대 200자로 제한한다. 빈 문자열은 nil로 저장한다.

패키지에 UI와 분리된 입력 값 타입을 둔다.

```swift
public struct SmileReflection: Equatable, Sendable {
    public let mood: String?
    public let momentNote: String?
}
```

`SessionRepository`는 방금 완료한 체크인의 회고를 한 번에 갱신하는 메서드를 제공한다. 기분과 메모를 버튼 탭마다 따로 저장하지 않는다.

## 5. 측정 흐름

### 촬영 화면

- 숫자 점수, 세로 게이지, “지금 미소 크기”를 제거한다.
- 얼굴이 감지되면 “편하게 숨을 쉬고 살짝 미소 지어보세요”를 표시한다.
- 조명·정면·카메라 오류 안내는 측정 가능성을 위한 것이므로 유지한다.
- 완료 버튼은 “오늘의 미소 남기기”로 변경한다.
- AR 측정은 저장 시 계속 수행하지만 사용자가 점수를 목표로 과도하게 표정을 만들도록 유도하지 않는다.

### 완료 화면

- 오늘/어제 점수와 상승 배지를 제거한다.
- “오늘도 잠시 웃어봤어요”를 중심 메시지로 표시한다.
- 현재 기분 선택은 유지한다.
- 선택적 한 줄 입력을 추가한다.
  - 질문: “오늘 나를 미소 짓게 한 순간이 있었나요?”
  - placeholder: “떠오르는 순간을 짧게 남겨보세요”
  - 보조 문구: “비워두어도 괜찮아요”
- 확인 버튼에서 기분과 한 줄 기록을 한 번에 저장한다.

## 6. 습관 피드백 로직

얼굴 측정 기반 `InsightEngine`은 기본 UX와 추천에서 분리한다. 새 `HabitEncouragementEngine`은 오직 행동 이력으로 격려 문구를 만든다.

입력:

- 오늘 미소 시간 횟수
- 현재 연속 일수
- 최근 7일 미소 기록 일수
- 직전 체크인 이후 경과 일수
- 한 줄 기록 유무

출력 예:

| 조건 | 문구 |
|---|---|
| 첫 기록 | “첫 미소 시간을 남겼어요. 내일도 부담 없이 들러보세요.” |
| 오늘 두 번째 이상 | “오늘 벌써 두 번째 미소예요. 잠깐의 여유가 하나 더 쌓였어요.” |
| 3일 이상 연속 | “연속 3일째 웃어보는 시간을 만들고 있어요.” |
| 공백 후 복귀 | “다시 돌아온 오늘이 새로운 시작이에요.” |
| 한 줄 기록 있음 | “오늘의 좋은 순간도 함께 남겼어요.” |
| 그 외 | “오늘의 미소 하나가 기록되었어요.” |

우선순위는 공백 후 복귀 → 첫 기록 → 하루 반복 → 연속 기록 → 한 줄 기록 → 기본 순서로 고정한다. 공백 일수 자체를 부정적으로 노출하지 않는다.

## 7. 홈과 기록

### 홈

- 반원 점수 게이지를 제거하고 오늘의 미소 완료 상태와 질문을 보여준다.
- 오늘 미완료: “오늘의 미소 시간” CTA.
- 오늘 완료: 체크 표시, 오늘 기록 횟수, 최근 한 줄 기록이 있으면 짧게 표시.
- 통계 카드는 “이번 주 웃어본 날”과 “남긴 좋은 순간”으로 변경한다.
- 7일 도트와 연속 일수는 유지하되 경쟁·실패 어조를 쓰지 않는다.
- 4주 기준선 재촬영은 점수 정확도 목적이므로 기본 홈 넛지에서 제거한다. 기준선 재설정은 설정의 진단/복구 기능으로만 남긴다.

### 기록

- 주간 점수 막대 차트와 7일 평균을 제거한다.
- 최근 7일은 날짜별 미소 시간 횟수 또는 완료 여부로 표시한다.
- 월간 히트맵은 “웃어본 날” 캘린더로 유지한다.
- 시간대별 점수 상세를 제거하고 아침·낮·저녁 미소 시간 횟수로 대체한다.
- 기분과 한 줄 기록이 있는 최근 항목을 날짜순으로 보여준다.
- 원시 얼굴 수치와 점수는 일반 기록 화면에서 표시하지 않는다.

## 8. 질문과 알림

현재 시간대별 질문 구조와 비반복 순환 로직은 유지하되, 타인의 시선이나 표정 평가를 암시하는 질문은 교체한다.

제거 대상 예:

- “지금 누군가 당신을 본다면 어떤 표정을 보고 있을까요?”
- “옆에 있는 사람이 본다면 편안해 보일 표정을 짓고 있나요?”

질문 카테고리:

- 아침: 기대되는 작은 순간, 나에게 건네는 표정
- 낮: 잠깐 숨 고르기, 최근 즐거웠던 순간
- 저녁: 오늘 고마웠던 일, 나를 웃게 한 사람이나 순간

알림은 명령형보다 초대형 문장으로 쓴다. 모든 질문은 미소를 짓지 못하거나 좋은 순간이 떠오르지 않는 상태도 허용해야 한다.

## 9. 쉬어가기 콘텐츠

기존 케어 탭의 얼굴 부위·붓기·점수 개선 중심 루틴과 추천은 제품 목적과 맞지 않는다.

- 탭 표시명: “케어” → “쉬어가기”
- 추천 기준: 얼굴 지표와 전날 점수 → 시간대와 최근 실천 여부
- 콘텐츠 방향:
  - 30초 숨 고르고 미소 짓기
  - 오늘의 좋은 순간 떠올리기
  - 고마운 사람 한 명 떠올리기
  - 어깨 힘을 빼고 편안하게 웃기
  - 누군가에게 따뜻한 표정 건네기
- 기존 `CareSession` 저장 모델은 데이터 호환을 위해 유지한다.
- UI·도메인 값 타입은 `SmilePractice`/`SmilePracticeViewModel`로 전환하고, 기존 `CareRoutine`/`CareViewModel`은 호출부 마이그레이션 후 제거한다.
- 기존 루틴 기록은 삭제하지 않는다. 새 카탈로그에서 찾을 수 없는 과거 `routineID`도 저장소에 그대로 남긴다.

## 10. 수익모델 정렬

`2026-07-24-pro-unlock-design.md`의 현재 유료 경계는 이 설계가 구현되기 전에는 실행하지 않는다.

무료:

- 하루 미소 시간
- 기본 시간대 질문
- 기분과 한 줄 좋은 순간 기록
- 최근 7일과 기본 캘린더
- 기본 쉬어가기 콘텐츠
- 리마인더 1개

Pro 후보:

- 아침·낮·저녁 다중 리마인더
- 전체 기록과 좋은 순간 보관함
- 주간 돌아보기
- 질문·쉬어가기 콘텐츠 팩
- 사용자 지정 질문
- 기록 내보내기

Pro는 얼굴 상세 분석이 아니라 **미소 습관을 오래 이어가고 좋은 순간을 다시 보는 기능**으로 설명한다. StoreKit 구현 전 Pro 설계·계획의 혜택 문구와 게이팅 규칙을 이 기준으로 다시 갱신한다.

## 11. 범위 제외

- 우울감, 불안, 정신건강 상태 진단
- 사용자의 감정이 좋아졌다고 단정하는 인과 표현
- 얼굴 점수 개선, 좌우 교정, 진짜 미소 판정
- 서버, 계정, 소셜 피드, 친구 순위
- AI 생성 코칭
- 이번 작업에서의 StoreKit 구현
- 위젯과 공유 확장

## 12. 완료 기준

- 홈·촬영·완료·기록·쉬어가기 기본 흐름에서 점수와 전날 대비 상승이 노출되지 않는다.
- 얼굴 지표는 측정 품질과 저장 호환에만 사용되며 사용자 습관을 평가하지 않는다.
- 체크인 완료 후 기분과 200자 이내 좋은 순간을 선택적으로 저장하고 다시 볼 수 있다.
- 미입력, 첫 기록, 연속 기록, 공백 후 복귀 모두 비난 없는 문구를 표시한다.
- 시간대별 알림 질문에 타인의 시선·외모 평가 문구가 없다.
- 기존 체크인, 기준선, 케어 기록이 삭제되지 않는다.
- `CoachingKit` 전체 테스트가 통과하고 앱 타깃이 빌드된다.
- TrueDepth 실기기에서 질문→미소→회고→기록 흐름이 완료된다.
