# 알림 중심 미소 습관 MVP 설계

- 날짜: 2026-07-28
- 상태: 승인됨
- 대체 문서: `2026-07-27-smile-habit-reframe-design.md`
- 배경: 사용자의 실제 문제는 평소 업무·이동·대인 상황에서 미소를 자주 잊고, 무표정이 강한 인상으로 전달될 수 있다는 점이다. 이 MVP는 감정 개선이나 좋은 이유 찾기가 아니라, 사용자가 정한 시간에 알림을 받고 짧게 표정을 의식해 웃는 행동을 반복하도록 돕는다.

## 1. 단일 문제와 가치

문제:

> 평소 미소를 짓고 싶지만 일상에서는 자주 잊는다.

가치:

> 원하는 시간에 알림을 받고, 10초 이내에 안내된 표정으로 웃어보게 한다.

핵심 루프:

```text
시간과 미소 가이드 선택
→ 로컬 알림
→ 가이드 화면 바로 열기
→ 5~10초 미소
→ 완료 기록
→ 오늘 횟수와 최근 7일 확인
```

이 루프에 직접 기여하지 않는 기능은 MVP에서 제외한다.

## 2. MVP 원칙

1. 알림 탭 후 한 번의 화면 전환으로 가이드를 시작한다.
2. 카메라·TrueDepth·기준선·점수 없이 동작한다.
3. 사용자가 웃었는지 검증하지 않는다. 완료는 자기 보고 방식이다.
4. 하루 여러 번의 알림을 핵심 무료 기능으로 제공한다.
5. 기록은 완료 시각과 가이드 종류만 저장한다.
6. 쉬어간 날을 실패로 표현하지 않는다.
7. “행복해진다”, “인상이 개선된다” 같은 효과를 약속하지 않는다.
8. 걷거나 운전하며 화면을 보도록 유도하지 않는다.

## 3. 포함 범위

### 알림

- 사용자가 여러 알림을 추가·수정·삭제·활성화할 수 있다.
- 첫 설정 권장값은 하루 3회이며 사용자가 온보딩에서 직접 확정한다.
- 각 알림에는 시간과 미소 가이드가 연결된다.
- 알림 탭 시 해당 가이드 화면을 바로 연다.
- 앱이 활성 상태일 때도 배너와 소리를 유지한다.
- 모든 알림은 온디바이스 `UNUserNotificationCenter`로 처리한다.

### 미소 가이드

MVP 카탈로그는 3개로 고정한다.

| ID | 이름 | 안내 | 기본 시간 |
|---|---|---|---|
| `soft-smile` | 편안한 미소 | 턱과 어깨 힘을 빼고 입꼬리를 살짝 올려보세요. | 5초 |
| `greeting-smile` | 인사 미소 | 눈가에 힘을 빼고 반갑게 인사하는 표정을 지어보세요. | 5초 |
| `bright-smile` | 활짝 미소 | 편한 만큼 밝게 웃어보세요. | 5초 |

- 안내는 텍스트, SF Symbol 또는 코드 기반 단순 얼굴 그래픽, 타이머로 구성한다.
- 새 이미지 생성이나 영상 제작은 MVP 필수 조건이 아니다.
- 사용자는 홈에서 즉시 하나를 선택해 수동 실행할 수도 있다.

### 기록

- 오늘 완료 횟수
- 최근 7일 날짜별 완료 여부와 횟수
- 이번 주 완료 일수
- 다음 예정 알림

점수, 평균, 얼굴 수치, 기분, 메모, 좋은 순간은 저장하거나 표시하지 않는다.

### 화면

1. 온보딩
   - 앱 목적
   - 알림이 필요한 이유
   - 권장 시간 3개와 각 가이드 선택
   - 사용자가 확정한 후 알림 권한 요청
2. 홈
   - “지금 미소 짓기”
   - 오늘 완료 횟수
   - 다음 알림
   - 최근 7일
   - 설정 진입
3. 미소 가이드
   - 가이드 이름과 안내
   - 5초 타이머
   - 완료 또는 닫기
4. 설정
   - 알림 CRUD
   - 시간별 가이드 선택
   - 알림 권한 상태 안내
   - 데이터 저장 위치

5개 탭 구조는 사용하지 않는다. `NavigationStack` 기반 홈과 설정, `fullScreenCover` 가이드면 충분하다.

## 4. 제외 범위

- 기준선 촬영과 재촬영
- ARKit 얼굴 추적
- 카메라 프리뷰
- 미소 점수와 실시간 게이지
- 어제 대비 상승·하락
- 좌우 비대칭, 긴장도, Duchenne 분석
- 기분 이모지
- 좋은 순간 한 줄 기록
- 감정·마음 회고
- 얼굴 케어와 마사지
- 점수 기반 추천
- 월간 상세 차트
- 스트릭 손실 강조
- 위젯, Apple Watch, 캘린더·위치 연동
- 사용자 지정 가이드 문구
- StoreKit, Pro, 구독
- 유료 광고

기존 코드는 즉시 모두 삭제하지 않고 새 흐름에서 연결을 끊는다. 실제 배포 이력과 데이터 마이그레이션 요구가 없다고 확인된 뒤 별도 정리 작업에서 삭제한다.

## 5. 데이터 모델

### `SmileGuide`

SwiftData가 아닌 고정 값 타입이다.

```swift
public struct SmileGuide: Identifiable, Equatable, Sendable {
    public let id: String
    public let title: String
    public let instruction: String
    public let notificationText: String
    public let durationSeconds: Int
}
```

`SmileGuideCatalog`는 위 3개를 고정 순서로 제공하고 알 수 없는 ID를 `soft-smile`로 안전하게 대체한다.

### `SmileMoment`

새 SwiftData 모델이다.

```swift
@Model
public final class SmileMoment {
    public var date: Date
    public var guideID: String
    public var sourceRawValue: String
}
```

`sourceRawValue`는 `manual` 또는 `notification`이다. 알 수 없는 값은 읽을 때 `manual`로 취급한다.

### `ReminderSetting`

기존 필드에 다음을 추가한다.

```swift
public var guideID: String? = nil
```

과거 알림은 nil일 수 있으며 스케줄링·표시 시 `soft-smile`을 기본값으로 사용한다.

### 기존 모델

`Baseline`, `CheckInSession`, `CareSession`은 업데이트 호환을 위해 당분간 `PersistenceSchema`에 유지한다. 새 MVP 흐름은 이 모델을 생성하거나 수정하지 않는다.

## 6. 알림 payload

새 payload는 최소 필드만 사용한다.

```swift
public struct ReminderNotificationPayload {
    public let reminderID: String
    public let guideID: String
}
```

- 새 알림은 `reminderID`와 `guideID`를 저장한다.
- 과거 `bucket`/`promptText` payload는 파싱 가능하면 `soft-smile`로 연결하거나 홈에 머문다.
- 알 수 없는 guide ID는 기본 가이드로 대체한다.
- 알림 탭으로 진입한 가이드를 완료하면 `SmileMoment.source = .notification`으로 기록한다.

## 7. 알림 문구

각 가이드의 알림 문구는 짧고 즉시 행동할 수 있어야 한다.

- 편안한 미소: “지금 5초만 입꼬리를 살짝 올려볼까요?”
- 인사 미소: “다음 사람을 만나기 전, 인사 미소를 준비해볼까요?”
- 활짝 미소: “잠시 멈춰 있다면 편한 만큼 밝게 웃어보세요.”

안전 원칙:

- “걷는 중 화면을 보세요” 같은 문구 금지
- 운전 중 사용 유도 금지
- 타인의 평가를 단정하지 않음
- 무표정을 잘못이나 결함으로 표현하지 않음

## 8. 완료 경험

- 타이머는 5초이며 화면을 열자마자 자동 시작하지 않는다.
- 사용자가 “시작”을 누르면 카운트다운을 시작한다.
- 타이머 종료 시 부드러운 햅틱과 “오늘의 미소를 남겼어요”를 표시한다.
- `SmileMoment`는 타이머가 끝난 뒤 한 번만 저장한다.
- 사용자가 중간에 닫으면 기록하지 않는다.
- 빠른 반복 탭과 화면 재표시로 중복 저장되지 않는다.
- 접근성을 위해 Reduce Motion에서는 숫자 전환만 사용하고 큰 애니메이션을 생략한다.

## 9. MVP 지표

제품 내부의 사용자용 지표:

- 오늘 완료 횟수
- 이번 주 완료 일수
- 최근 7일 활동

검증 질문:

- 알림을 받은 사용자가 실제로 미소를 의식했는가?
- 알림 탭 후 완료까지 복잡하다고 느꼈는가?
- 하루 알림 빈도가 부담스러웠는가?
- 어떤 가이드를 가장 자주 선택했는가?

서버 분석을 추가하지 않는다. TestFlight 또는 소규모 사용성 확인에서 사용자 인터뷰와 화면의 로컬 기록을 바탕으로 검증한다.

## 10. 수익화와 홍보

- MVP 검증 전 StoreKit과 유료 광고를 구현하지 않는다.
- 유료 설치를 구매하지 않고 TestFlight, 지인, 직접 모집으로 5~10명을 확보한다.
- 최소 7일 사용 후 “알림 때문에 미소를 의식했다”는 반복 응답과 실제 완료 기록을 확인한다.
- 핵심 루프가 검증된 뒤 별도 수익화 설계에서 유료 앱, 1회 구매 또는 추가 가이드 팩을 비교한다.
- 다중 알림 자체는 사용자의 핵심 문제이므로 검증 단계에서 잠그지 않는다.

## 11. 완료 기준

- 기준선과 카메라 없이 첫 실행부터 사용할 수 있다.
- 3개 가이드와 여러 알림을 설정할 수 있다.
- 알림을 탭하면 선택된 가이드가 열린다.
- 수동·알림 진입 모두 타이머 완료 후 정확히 한 번 기록된다.
- 홈에서 오늘 횟수, 이번 주 일수, 최근 7일을 확인할 수 있다.
- 사용자 화면에 점수, 얼굴 분석, 감정 기록, 케어가 없다.
- 기존 SwiftData 모델과 저장 데이터가 삭제되지 않는다.
- 전체 패키지 테스트와 앱 빌드가 통과한다.
- 알림 허용·거부, 앱 종료 상태, 포그라운드 상태를 실기기에서 확인한다.
