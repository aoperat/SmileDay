## 0. 개정 이력

### 2026-07-30 개정 (5차) — 세션 그래프와 비율, 분당 스냅샷

세션이 끝나면 아무것도 남지 않던 문제를 고친다. 자세한 설계는 `2026-07-30-live-smile-session-graph-design.md`에 있고, 여기서는 이 문서의 조항 변경만 적는다.

**약속의 경계가 또 한 겹 갈린다.** 2차 개정에서 "표시하지 않는다"와 "저장하지 않는다"를 분리했고, 이번에는 **"집지 않는다"와 "저장하지 않는다"를 분리한다.**

| 약속 | 이전 | 이후 |
|---|---|---|
| 카메라 영상 표시 | 기본 꺼짐, 토글로 켬 | 변경 없음 |
| 사진을 집는 것 | 하지 않음 | **분당 1장, 세션 한정** |
| 저장·전송 | 하지 않음 | 하지 않음 (변경 없음) |

절대 조항으로 남는 것은 저장·전송 금지뿐이다.

### 2026-07-29 개정 (4차) — 인식률 우선, 허용 각도 15° → 40°

**정확도보다 인식률을 우선한다.**

15°는 좁았다. 세워둔 기기를 곁눈으로 보며 일하는 상황에서 시선이 계속 범위를 벗어나면 단계 표시가 비어 있을 뿐 아니라, 3차 개정에서 넣은 알림 타이머까지 멈춘다. **알림이 가장 필요한 상황에서 알림이 울리지 않는다.** 두 기능이 서로를 무력화하고 있었다.

40°에서는 반대쪽 입꼬리가 짧아 보여 계수가 덜 정확하다. 그 대가를 받아들인다 — 값이 조금 부정확한 것보다 인식이 아예 끊기는 쪽이 나쁘다.

각도 계산은 순수 기하라 `CoachingKit`의 `LiveSmileGaze`로 옮겨 테스트로 고정했다. **화면 중앙에서 벗어나도 인식돼야 한다**는 요구를 `LiveSmileGazeTests`가 직접 검증한다.

### 2026-07-29 개정 (3차) — 웃지 않을 때 알리기, 프리뷰 좌우반전 제거

**(1) 웃지 않는 시간이 이어지면 부른다.**

세워둔 기기를 계속 보고 있을 리 없다. 단계가 `resting`으로 일정 시간 이어지면 진동과 알림으로 `Smile!`을 알린다. 간격과 진동 여부는 설정 화면에서 바꾼다.

얼굴이 안 보이거나 어두워서 판단할 수 없는 동안은 **시간을 세지 않는다**. 자리를 비운 시간까지 세면 돌아오자마자 알림이 뜬다. 대신 그때까지 쌓인 시간은 버리지 않는다.

**(2) 프리뷰 좌우반전을 없앴다.**

2차 개정에서 셀피 관례를 따라 거울처럼 뒤집었는데, 되돌린다. 카메라가 보는 그대로 보여준다.

### 2026-07-29 개정 (2차) — 카메라 화면을 선택형으로 허용

원래 설계는 카메라 프리뷰를 범위 제외로 두고 "표시하지 않는다"를 약속으로 삼았다. 이를 바꿔, **기본값은 표시하지 않되 사용자가 버튼으로 켜고 끌 수 있게** 한다.

배경: 미소를 연습하는 동안 자기 표정을 확인하고 싶은 것은 자연스러운 요구다. 프리뷰를 원천 차단하면 이 모드를 쓸 이유 자체가 줄어든다.

**약속의 경계가 바뀐다.** 이전에는 "표시하지 않는다"와 "저장하지 않는다"가 함께 묶여 있었는데, 이제 둘을 분리한다.

| 약속 | 이전 | 이후 |
|---|---|---|
| 카메라 영상을 화면에 표시 | 하지 않음 | **기본 꺼짐, 사용자가 켤 수 있음** |
| 사진·영상·측정값 저장 | 하지 않음 | 하지 않음 (변경 없음) |
| 네트워크 전송 | 하지 않음 | 하지 않음 (변경 없음) |

표시 여부와 무관하게 저장·전송하지 않는다는 약속은 그대로다. 사용자 문구와 `NSCameraUsageDescription`에서 이 구분이 흐려지지 않게 한다.

### 2026-07-29 개정 (1차) — 구현 중 사용자 피드백 반영

승인 후 구현 과정에서 두 가지를 바꿨다. 결정 배경을 남긴다.

**(1) 0–100 점수를 4단계 표시로 바꿨다.**

매 프레임 바뀌는 두 자리 숫자는 산만하고, 숫자가 크게 떠 있으면 센서 값이 아니라 성적표로 읽힌다. 화면에서 숫자를 완전히 없애고 채워지는 칸으로만 보여준다. 0–1 신호는 계산 내부에만 남는다.

**(2) 정면 판정을 "카메라를 보고 있는가"로 바꿨다.**

원래 설계는 얼굴의 pitch/yaw를 각각 ±15°로 봤다. 그런데 이 각도는 고정된 기준 축에 대한 머리 방향이라, 화면 정면에서 비켜 앉은 사용자가 고개를 돌려 카메라를 정확히 바라봐도 각도가 벗어난 것으로 잡힌다. 50cm 거리에서 좌우 13cm만 벗어나도 걸린다. 거치대에 세워두고 쓰는 사용 맥락에서 이건 잘못된 제약이다.

얼굴이 향하는 방향을 **얼굴에서 카메라로 향하는 방향**과 비교하도록 바꿨다. 화면 중앙에 있을 필요가 없어지고, 판정에 남는 건 "카메라 쪽을 보고 있는가" 하나다.

## 1. 제품 판단

사용자가 iPhone을 책상이나 거치대에 세워두고 일하는 동안, 현재 미소가 카메라에 어느 정도 감지되는지 즉시 확인할 수 있는 선택형 모드를 제공한다.

이 기능은 외모·감정·인상을 평가하는 점수표가 아니다. 사용자가 웃는 행동을 시작하고 잠시 이어가는 데 도움을 주는 실시간 센서 피드백이다.

핵심 흐름:

```text
홈에서 "실시간 미소 확인" 선택
→ 카메라 사용 안내와 권한 확인
→ 편한 표정 2초 보정
→ 현재 미소 단계와 상태 표시 (카메라 화면은 원할 때만)
→ 사용자가 닫으면 즉시 측정 종료
```

## 2. 제품 내 위치

- 기존 알림 → 문구 → 5초 미소 → 완료 기록 루프는 그대로 유지한다.
- 실시간 확인은 홈의 보조 행동이며 온보딩 필수 단계가 아니다.
- 알림을 탭했을 때 자동으로 카메라를 켜지 않는다.
- 사용자가 명시적으로 시작할 때만 카메라 권한을 요청하고 세션을 시작한다.
- TrueDepth가 없는 기기에서도 기존 빈도 중심 기능은 모두 사용할 수 있다.

## 3. 화면 경험

### 진입

홈의 기본 CTA `지금 한 번 웃기` 아래에 보조 CTA를 둔다.

```text
실시간 미소 확인
카메라 화면 없이 미소 신호만 보여드려요.
원하면 화면을 켤 수도 있어요.
```

첫 진입 전 다음을 명확히 알린다.

- 전면 TrueDepth 카메라가 켜짐
- 카메라 화면은 기본으로 꺼져 있고, 버튼으로 켜고 끌 수 있음
- 화면을 켜든 끄든 사진·영상·측정값을 저장하지 않음
- 사용 중 iOS의 초록색 카메라 표시가 나타남
- 화면을 켜두는 동안 배터리가 평소보다 빨리 줄어듦

### 측정 화면

화면은 다음 요소로 구성한다.

- 상단 닫기 버튼
- `카메라 사용 중 · 영상과 측정값은 저장하지 않아요` 고지 (측정 내내 보임)
- `카메라 화면 보기` / `카메라 화면 숨기기` 토글
- 토글이 켜져 있을 때만 나타나는 카메라 화면
- 레이블 `지금 미소 신호`
- 채워지는 4칸 단계 표시
- 한 줄 즉각 피드백
- 얼굴·조명·방향 문제가 있을 때의 우선 안내
- `다시 보정`과 `종료`

**숫자를 표시하지 않는다.** 프레임마다 바뀌는 숫자는 읽기 어렵고, 크게 떠 있으면 센서 값이 아니라 평가로 읽힌다.

### 카메라 화면 토글

- 기본값은 꺼짐이다. 화면을 열자마자 얼굴이 뜨지 않는다.
- 매 세션 꺼진 상태로 시작한다. 이전 선택을 저장하지 않는다.
- 켜져 있을 때만 프리뷰 뷰를 만든다. 끄면 뷰가 사라져 렌더링 비용도 사라진다.
- 좌우를 뒤집지 않는다. 카메라가 보는 그대로 보여준다.
- 측정이 돌고 있을 때만 보여준다. 보정 중, 백그라운드 복귀 대기, 실패 화면에서는 나타나지 않는다.
- 얼굴 메시나 3D 오버레이를 그리지 않는다. 카메라 배경만 보여준다.
- 접근성 트리에서는 숨긴다. 화면을 읽어줄 내용이 없고, 단계와 상태 안내가 이미 있다.

화면을 켜두는 사용 목적에 맞게 측정 중에는 자동 잠금을 막고, 화면을 닫거나 백그라운드로 가면 원래 상태로 복원한다.

## 4. 신호와 단계의 의미

내부 신호는 ARKit의 좌우 `mouthSmile` blend shape가 세션 시작 시 편한 표정에서 얼마나 증가했는지를 0~1로 정규화한 값이다. 이 값은 화면에 나오지 않고 단계로 묶여서만 보인다.

다음은 신호에 포함하지 않는다.

- 외모나 인상
- 감정 상태
- Duchenne smile 판정
- 좌우 대칭에 대한 감점
- 미간·주름·나이 관련 값
- 다른 사용자와의 비교
- 과거 세션과의 순위

사용자 설명:

> 이 표시는 웃음의 좋고 나쁨이 아니라, 지금 카메라가 감지한 입꼬리 움직임을 보여줘요.

## 5. 세션 보정

사람과 카메라 위치에 따른 차이를 줄이기 위해 매 세션 시작 시 편한 표정을 2초간 측정한다.

보정 규칙:

- 얼굴이 추적되고 카메라를 보고 있으며 조명이 충분한 프레임만 사용한다.
- 유효 프레임이 부족하면 보정 시간을 연장한다.
- 보정 중에는 단계를 보여주지 않고 `편한 표정으로 잠시 바라봐주세요`를 표시한다.
- 보정값은 메모리에만 유지하며 화면을 닫으면 폐기한다.
- 사용자가 보정 중 이미 웃고 있으면 단계 변화 폭이 작을 수 있으므로 `다시 보정` 버튼을 제공한다.
- 품질 문제로 잠시 끊겼다가 돌아올 때는 다시 보정하지 않는다. 잠깐 고개를 돌린 것으로 편한 표정을 다시 모을 이유가 없다.

초기 권장 계산:

```swift
let smileMean = (mouthSmileLeft + mouthSmileRight) / 2
let relativeSignal = max(0, smileMean - neutralSmileMean)
let signal = min(relativeSignal / 0.45, 1)   // 0~1, 화면에는 나오지 않는다
```

`0.45`는 제품 효과를 뜻하는 임계값이 아니라 표시 범위를 위한 초기 센서 스케일이다. TrueDepth 실기기 검증에서 다양한 얼굴·거리·조명 조건으로 조정한다.

## 6. 안정화와 단계

ARKit 프레임마다 값을 그대로 반영하면 표시가 흔들리므로 지수 이동 평균을 사용한다.

```swift
smoothed = alpha * current + (1 - alpha) * previous
```

- 초기 `alpha`: `0.2`
- UI 갱신 상한: 초당 10회
- 단계 경계에는 hysteresis(신호 `0.03`)를 적용해 표시가 빠르게 왕복하지 않게 한다.

### 단계 구간

**구간을 균등하게 4등분하지 않는다.**

| 단계 | 신호 구간 | 폭 | 표시 문구 |
|---|---|---:|---|
| `resting` | 0 ~ 0.10 | 0.10 | `편하게 있다가 천천히 미소 지어보세요.` |
| `starting` | 0.10 ~ 0.30 | 0.20 | `미소 신호가 올라오고 있어요.` |
| `holding` | 0.30 ~ 0.60 | 0.30 | `미소가 이어지고 있어요.` |
| `clear` | 0.60 ~ 1.0 | 0.40 | `미소 신호가 또렷하게 잡혀요.` |

아래를 좁게 둔 이유는 편한 표정에서 벗어나는 첫 변화를 바로 알아차리게 하기 위해서다. 위를 넓게 둔 이유는 더 크게 웃으라고 밀지 않기 위해서다. 균등 분할은 두 목적 모두에 어긋나므로 "정리" 대상이 아니다.

색상은 실패·성공의 빨강/초록 판정이 아니라 살구 → 코랄의 연속 변화로 표시한다.

피드백 기본값은 시각 정보다. 반복 소리나 음성은 업무 방해와 사생활 노출 가능성이 있어 첫 범위에서 제외한다. 높은 단계에 처음 진입할 때의 약한 햅틱은 설정 가능한 후속 항목으로 둔다.

## 6-1. 웃지 않을 때 알리기

기기를 세워두고 다른 일을 하는 동안 화면만 바뀌면 알아채지 못한다. 단계가 `resting`으로 설정한 시간만큼 이어지면 부른다.

- 기본 간격 `60초`. 설정에서 `30 / 60 / 90 / 120 / 180초` 중 고른다.
- 진동은 켜고 끌 수 있다. 알림 전체도 끌 수 있다.
- 알리는 채널: 진동(설정), 로컬 알림 배너, 화면의 `Smile!` 표시.
- 알린 뒤 0부터 다시 세므로, 계속 웃지 않으면 같은 간격으로 다시 부른다.
- 한 번이라도 `resting`을 벗어나면 처음부터 다시 센다.
- **얼굴이 없거나, 카메라를 보지 않거나, 어둡거나, 보정 중일 때는 세지 않는다.** 웃는지 알 수 없는 시간이다. 다만 그때까지 쌓인 시간은 남긴다.
- 다시 보정하면 쌓인 시간도 버린다.

진동은 성공·실패 알림음이 아니라 가볍게 두드리는 느낌(`impact medium`)으로 둔다. 평가가 아니라 신호다.

알림 배너에는 딥링크 정보를 싣지 않는다. 사용자는 이미 이 화면에 있으므로 탭해도 5초 미소 화면으로 보내지 않는다. 같은 식별자를 재사용해 배너가 쌓이지 않게 한다.

알림 권한이 없으면 배너만 조용히 빠지고 진동과 화면 표시는 그대로 동작한다. 이 모드가 권한을 새로 요청하지는 않는다.

설정값은 사용자 환경설정이라 `UserDefaults`에 저장한다. 측정값을 저장하지 않는다는 약속과는 별개다 — 여기에 얼굴이나 신호는 들어가지 않는다.

## 7. 측정 품질 상태

품질 문제가 있으면 단계보다 원인을 먼저 보여주고 단계 표시를 비운다. 믿을 수 없는 표시를 남겨두면 그 값이 현재 표정으로 읽힌다.

우선순위:

1. 카메라 권한 없음
2. TrueDepth 미지원
3. 세션 오류
4. 얼굴을 찾지 못함
5. 카메라를 보고 있지 않음
6. 조명이 너무 어두움
7. 보정 중
8. 정상 단계

권장 문구:

- `얼굴이 카메라에 들어오도록 기기를 조정해주세요.`
- `카메라 쪽을 편하게 바라봐주세요.`
- `조금 더 밝은 곳에서 사용해주세요.`
- `이 기기에서는 실시간 미소 확인을 사용할 수 없어요.`
- `카메라 권한이 필요해요. 설정에서 허용해주세요.`

### 방향 판정

**화면 중앙에 있어야 한다는 조건은 없다.** 얼굴 위치는 판정에 쓰지 않는다. 이 요구는 `LiveSmileGazeTests`가 고정한다 — 좌우 80cm, 위 60cm까지 비켜 앉아도 카메라를 보고 있으면 통과해야 한다.

얼굴이 향하는 방향과, 얼굴 위치에서 카메라를 향하는 방향 사이의 각도를 잰다. 허용 범위는 `40°`다.

**정확도보다 인식률을 택한 값이다.** 이 각도에서는 반대쪽 입꼬리가 짧아 보여 계수가 덜 정확하다. 그래도 세워둔 기기를 곁눈으로 보며 쓰는 상황에서 인식이 아예 끊기는 쪽이 더 나쁘다고 판단했다. 좁히려면 실기기에서 실제 앉은 자세로 인식이 끊기지 않는지 먼저 확인한다.

```swift
let faceInCamera = simd_mul(simd_inverse(cameraTransform), faceTransform)
let toCamera = simd_normalize(-facePosition)          // 얼굴 → 카메라
let offset = acos(dot(normalize(faceForward), toCamera))
```

카메라 축과 비교하지 않는 이유는 개정 이력 (2)에 적었다. 이 방식에서는 옆으로 비켜 앉아도 카메라 쪽을 보면 통과하고, 화면 정면에 있어도 딴 곳을 보면 걸린다.

조명은 밝기 추정값이 `300 lux` 아래일 때만 어두움으로 본다. 추정값을 아직 받지 못한 상태(`nil`)는 어두움으로 단정하지 않는다 — 그러면 시작하자마자 조명 안내가 뜬다.

## 8. 카메라와 프라이버시

- `ARFaceTrackingConfiguration`을 사용한다.
- 카메라 화면은 사용자가 토글을 켰을 때만 표시한다. 기본값은 꺼짐이다.
- 프리뷰는 이미 돌고 있는 세션을 `ARSCNView`로 그리기만 한다.
- `ARFrame.capturedImage`는 **분당 1회 스냅샷을 축소 변환할 때만** 읽는다. 프레임마다 변환하거나 영상으로 잇지 않는다.
- 얼굴 anchor에서 좌우 `mouthSmile` 두 계수와 얼굴 방향, 조명 품질만 메모리에서 처리한다.
- **사진, 영상, raw frame, blend shape, 신호, 단계, 평균, 최고값, 세션 시간을 SwiftData나 UserDefaults에 저장하지 않는다. 이 약속은 카메라 화면 표시 여부와 무관하다.**
- 분당 스냅샷 외에는 촬영·캡처 기능을 만들지 않는다. 캡처 버튼, 내보내기, 공유 경로는 없다.
- 네트워크 전송을 추가하지 않는다.
- 화면 캡처를 앱이 강제로 막는 기능은 범위에 포함하지 않는다.

## 9. 생명주기와 자원 관리

- 화면 표시 후 사용자가 시작을 누를 때 ARSession을 실행한다.
- 화면 닫기, 앱 background, scene inactive에서 즉시 `pause()`한다.
- foreground 복귀 시 자동으로 재개하지 않고 사용자의 재시작을 받는다.
- 세션 종료 시 callback과 메모리 보정값을 해제한다.
- 측정 중 `UIApplication.shared.isIdleTimerDisabled = true`, 종료 시 이전 값을 복원한다.
- 중복 `start()`와 `stop()`은 안전하게 무시한다. `stop()` 뒤 늦게 도착한 이벤트도 무시한다.
- 장시간 사용 시 발열과 배터리 소모 안내를 짧게 제공한다.

## 10. 아키텍처

### CoachingKit

플랫폼 독립 타입과 테스트 가능한 계산만 둔다.

```swift
public struct LiveSmileSample: Equatable, Sendable {
    public let mouthSmileLeft: Double
    public let mouthSmileRight: Double
    /// 얼굴이 향하는 방향이 카메라를 바라보는 방향에서 벗어난 각도. 위치와 무관하다.
    public let gazeOffsetDegrees: Double
    public let ambientIntensity: Double?
}

@MainActor
public protocol LiveSmileMonitoring: AnyObject {
    var onEvent: ((LiveSmileMonitorEvent) -> Void)? { get set }
    func start()
    func stop()
}

public enum LiveSmileSignalEvaluator {
    /// 0~1. 화면에 숫자로 내보내지 않는다.
    public static func signal(sample: LiveSmileSample, neutralSmileMean: Double) -> Double
    public static func isFacingCamera(_ sample: LiveSmileSample) -> Bool
    public static func isTooDark(_ sample: LiveSmileSample) -> Bool
}

public enum LiveSmileLevel: Int, CaseIterable, Equatable, Sendable {
    case resting, starting, holding, clear
}

public struct LiveSmileNudgeSettings: Equatable, Sendable {
    public var isEnabled: Bool
    public var intervalSeconds: Int
    public var isHapticEnabled: Bool
}

@MainActor
public protocol LiveSmileNudging: AnyObject {
    func nudge(withHaptic: Bool)
}
```

설정은 `LiveSmileNudgeSettingsStoring`(UserDefaults + InMemory)이 보관한다. 언제 부를지는 `LiveSmileMonitorViewModel`이 정하고, 진동과 알림은 앱 타깃이 담당한다.

`LiveSmileMonitorViewModel`이 보정, smoothing, 품질 우선순위, UI 갱신 제한과 상태 전이를 담당한다. 밖으로 내보내는 값은 `state`와 `level`뿐이며 숫자는 내보내지 않는다. 저장소 의존성을 갖지 않는다 — 구조적으로 저장할 수 없게 둔다.

### 앱 타깃

- `ARKitLiveSmileMonitor`: ARKit anchor와 카메라 자세를 `LiveSmileSample`과 상태 이벤트로 변환. 프리뷰가 그릴 세션도 여기서 내준다
- `LiveSmileMonitorView`: 단계·상태 UI와 카메라 화면 토글
- `LiveSmileCameraPreview`: 켜져 있을 때만 존재하는 `ARSCNView` 래퍼. 세션을 넘겨받으면 샘플 delegate를 되돌려 측정이 끊기지 않게 한다
- `LiveSmileNudgeNotifier`: 진동과 로컬 알림 전달
- 설정 화면: 알림 켜기/끄기, 간격, 진동 여부
- 홈: 보조 진입 버튼과 full-screen presentation
- 카메라 권한, 설정 앱 이동, idle timer는 앱 타깃에서 처리

과거 `FaceMeasurement`, `ScoreCalculator`, `CoachingViewModel`, `CameraPreviewView`를 복원하지 않는다.

## 11. 저장과 지표

첫 버전에서는 다음을 저장하지 않는다.

- 신호·단계 시계열
- 평균·최고값
- 측정 시간
- 품질 오류 횟수
- 얼굴 측정값

기존 `SmileMoment` 완료 횟수에도 자동으로 포함하지 않는다. 사용자가 실시간 확인 모드를 켠 것과 5초 미소를 완료한 것은 다른 행동이기 때문이다.

사용자 검증 후 필요성이 확인되면 `실시간 확인 사용 시간`이 아니라 `사용자가 직접 완료로 남긴 횟수`만 별도 설계에서 검토한다.

## 12. 접근성

- 단계 표시는 색상만으로 구분하지 않고 문구를 함께 보여준다.
- VoiceOver가 초당 여러 번 값을 읽지 않도록 단계 표시를 자주 갱신되는 요소로 만들지 않는다.
- 단계나 품질 상태가 바뀔 때만 접근성 알림을 제공한다.
- 접근성 값은 `4단계 중 2단계` 형태로 읽어준다.
- Dynamic Type에서 문구가 잘리지 않게 한다.
- Reduce Motion에서는 칸이 채워지는 보간 애니메이션을 줄인다.

## 13. 범위 제외

- 카메라 화면을 기본으로 켜두거나, 토글 선택을 저장하는 것
- 화면에 표시하는 숫자 점수
- 영상 촬영, 사진·영상 저장, 내보내기·공유
- 고정 창(1분/5분/10분/1시간), 발생 횟수, 날짜별 비교
- 백그라운드 카메라 동작
- 신호 기록과 차트
- 얼굴 대칭·주름·나이·인상 평가
- 감정 추론
- 자동 완료 기록
- 여러 얼굴 동시 측정
- 일반 전면 카메라 기반 Vision 대체 구현
- 반복 음성 코칭

## 14. 완료 기준

- 사용자가 명시적으로 시작한 동안에만 TrueDepth 카메라가 동작한다.
- 카메라 화면은 기본으로 꺼져 있고, 토글로 켜고 꺼진다. 매 세션 꺼진 상태로 시작한다.
- 카메라 화면을 켜도 단계 측정이 끊기지 않는다.
- 화면에 숫자 점수가 없다.
- 웃지 않는 상태가 설정한 시간만큼 이어지면 진동·알림·화면 표시로 부른다.
- 얼굴이 보이지 않는 동안은 그 시간을 세지 않는다.
- 편한 표정 보정 후 4단계 표시가 부드럽게 갱신된다.
- 화면 중앙에 있지 않아도, 카메라 쪽을 보고 있으면 정상 측정된다.
- 얼굴 이탈·방향·조명 문제가 단계보다 먼저 안내된다.
- 닫기·백그라운드에서 측정과 화면 켜짐 유지가 즉시 종료된다.
- 사진·영상·blend shape·신호·단계가 저장되거나 전송되지 않는다.
- 기존 알림·5초 미소·완료 횟수 기능은 카메라 권한 없이 그대로 동작한다.
- `CoachingKit` 전체 테스트와 iOS 17 앱 빌드가 통과한다.
- TrueDepth 실기기에서 권한, 프리뷰 부재, 단계 반응, 비켜 앉은 자세, 장시간 자원 사용을 검증한다.
