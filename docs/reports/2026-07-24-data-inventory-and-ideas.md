## 1. 수집 데이터 총괄표

### 1-1. 체크인 측정 — `CheckInSession` (하루 1회 이상, 측정 종료 시 저장)

| 분류 | 필드 | 타입 | 설명 |
|---|---|---|---|
| 기본 | date | Date | 측정 시각 |
| 표정 | mouthCornerLeft / Right | Double | 입꼬리 좌/우 강도 (0~1) |
| 표정 | browTension | Double | 눈썹 긴장도 (browDown 좌/우 + browInnerUp 평균) |
| 환경 | lightingQuality | Double | 조명 품질 (0~1) |
| 환경 | deviceAngleOK | Bool | 정면 각도 허용범위 내 여부 |
| 점수 | scoreDelta | Double | 기준선(Baseline) 대비 변화량 |
| 세션 통계 | smileMean / smileMax | Double? | 세션 중 미소 강도의 평균/최대 |
| 세션 통계 | smileStability | Double? | 미소 강도 표준편차 (낮을수록 안정) |
| 세션 통계 | smileAsymmetry | Double? | 좌−우 입꼬리 차이의 세션 평균 |
| 세션 통계 | duchenneScore | Double? | 눈가(eyeSquint)+볼(cheekSquint) 기반 "진짜 미소" 지표 |
| 주관 입력 | mood | String? | 기분 이모지 (😊🙂😐😞😫), 미선택 시 nil |
| 확장 | payload / payloadVersion | Data? / Int | 아래 1-2 참조 |

### 1-2. 체크인 확장 페이로드 — `CheckInPayload` (JSON, `CheckInSession.payload`에 저장)

| 필드 | 내용 |
|---|---|
| blendshapesFinal | ARKit 블렌드셰이프 **52개 전체**의 측정 확정 시점 값 (눈 깜빡임/시선, 턱, 입 모양 전부 포함) |
| sessionStats | 선별 지표 12개 + 파생 3개(smile/asymmetry/duchenne)의 세션 mean/max/std |
| pitchDegrees / yawDegrees | 얼굴 각도 원본 (도 단위) |
| captureDurationSeconds | 측정 세션 길이 |
| trackingLossCount | 트래킹 끊김 횟수 (가림/이탈) |

선별 지표 12개: mouthSmile L/R, browDown L/R, browInnerUp, eyeSquint L/R, cheekSquint L/R, jawOpen, mouthPress L/R

### 1-3. 케어 루틴 행동 — `CareSession` (완주 + 중도 이탈 모두 저장)

| 필드 | 설명 |
|---|---|
| date / routineID | 종료 시각, 루틴 식별자 |
| startedAt / durationSeconds | 시작 시각, 실제 소요 시간 |
| completedSteps / totalSteps | 완료 단계 수 / 전체 단계 수 |
| wasCompleted | 완주 여부 (이탈 시 false) |

### 1-4. 기타

| 저장소 | 데이터 | 설명 |
|---|---|---|
| `Baseline` | 기준선 표정값 + 촬영 시각 | 모든 점수의 비교 기준. 4주 경과 시 재설정 권장 |
| `ReminderSetting` | 알림 시각/활성 여부 | 사용자가 설정한 리마인더 |
| UserDefaults | 케어 즐겨찾기, 리마인더 넛지 상태, 프롬프트 커서 | 선호/UX 상태 |

**수집 원칙: 사진·영상 원본은 저장하지 않음. 수치만, 온디바이스만, 서버 전송 없음.**

## 2. 데이터별 활용 아이디어 (단독 활용)

| 데이터 | 제공 가능한 정보 | 난이도 |
|---|---|---|
| scoreDelta 추이 | 일/주/월 변화 그래프, 개선률 (일부 구현됨) | 하 |
| smileAsymmetry | "왼쪽 입꼬리가 덜 올라가요" 편측 코칭 → 비대칭 교정 루틴 추천 | 하 |
| duchenneScore | 억지 미소 vs 진짜 미소 구분, "표정 품질 점수" | 하 |
| smileStability | 미소 유지력 추적 — "근육 컨트롤이 좋아지고 있어요" | 하 |
| smileMax | 컨디션 지표 — "오늘 최대 미소가 평소의 80%예요" | 하 |
| browTension | 긴장도 높은 날 릴랙스 루틴 자동 추천 | 하 |
| trackingLossCount, pitch/yaw | 측정 신뢰도 배지 — "이 기록은 자세가 흔들려 참고용이에요" | 하 |
| mood 히스토리 | 주간 기분 캘린더, 기분 분포 통계 | 하 |
| CareSession 완주율 | 루틴별 이탈 지점 분석 → 난이도 조정, "이 스텝에서 많이 그만둬요" | 중 |
| durationSeconds | 루틴 예상 시간 보정, "실제로는 4분 걸려요" | 중 |
| 시간대 패턴 | "당신은 아침형 — 아침 체크인 점수가 평균 +0.3° 높아요" | 중 |
| 블렌드셰이프 47개 (미사용분) | 신규 코칭 카테고리 재료: 턱 긴장(jawForward/mouthPress), 눈 피로(eyeBlink/eyeSquint 패턴), 입 오므림 습관 등 | 중~상 |

## 3. 내부 데이터 조합 아이디어

| 조합 | 제공 가능한 정보 | 비고 |
|---|---|---|
| **케어 완주 × 다음날 scoreDelta** | **루틴 효과 검증** — "리프팅 루틴을 한 다음날, 점수가 평균 +0.4° 높았어요" | 핵심. 앱의 존재 이유를 데이터로 증명. 구독 셀링포인트 1순위 |
| mood × 표정 지표 | "긴장도가 높은 날은 기분도 낮은 경향" — 무드/표정 상관 리포트 | 데이터 2~4주 축적 필요 |
| mood × 케어 실행 | "케어를 한 날 기분이 좋다고 답한 비율이 30% 높아요" — 습관 동기부여 | |
| 시간대 × scoreDelta × mood | 개인 최적 체크인/케어 타이밍 추천 → 리마인더 시각 자동 제안 | 기존 리마인더와 연결 |
| smileAsymmetry 추이 × 루틴 카테고리 | 비대칭 개선에 실제 효과 있었던 루틴 식별 → 개인화 추천 강화 | |
| 스트릭 × 개선 속도 | "연속 7일 체크인한 주에 개선 속도가 2배" — 리텐션 메시지 재료 | |
| duchenneScore × smileMax | "미소는 커졌는데 눈은 안 웃어요" — 표정 자연스러움 코칭 | |
| 완주율 × 루틴 길이 | 이탈 잦은 사용자에게 1분 루틴 우선 노출 | |
| Baseline 나이 × scoreDelta 안정화 | 점수가 기준선에 수렴하면 재설정 시점 제안 정확도 향상 | |

## 4. 외부 데이터 조합 아이디어 (신규 연동 필요)

| 외부 소스 | 조합 | 제공 가능한 정보 | 비용/마찰 |
|---|---|---|---|
| **HealthKit 수면** | 수면시간 × 붓기/처짐 지표 | "6시간 미만 잔 날, 아침 붓기 지표가 20% 높아요" → 붓기 루틴 자동 추천 | 권한 1회, 구현 중 |
| HealthKit 마음챙김/운동 | 운동일 × 표정/기분 | "운동한 날 진짜 미소 지수가 높아요" | 권한 동일 |
| HealthKit 생리주기 | 주기 × 붓기 지표 | 주기 기반 붓기 예측·케어 타이밍 안내 | 민감정보 — 명시적 옵트인 필수 |
| 날씨 API | 일조량/흐림 × mood/표정 | "흐린 날 기분이 낮아지는 편이에요" + 실내 케어 제안 | API 비용 소액, 위치 권한 |
| 캘린더 (EventKit) | 일정 밀도 × browTension | "일정 많은 날 미간 긴장이 올라가요" → 바쁜 날 1분 릴랙스 푸시 | 권한 민감, 일정 내용은 읽지 않고 개수만 |
| 시즌/공휴일 | 연휴 × 스트릭 패턴 | 이탈 위험 시기 예측 → 선제 넛지 | 무료 |
| LLM (서버) | 위 전부 × 자연어 생성 | **주간 AI 리포트**: 모든 지표를 자연어 요약 + 다음 주 목표 제안. **AI 코치 멘트**: 내 데이터를 아는 트레이너 톤의 데일리 코멘트 | 호출당 비용. 구독 기능으로 적합 |

## 5. 수익모델 관점 우선순위 제안

무료 (습관 형성·리텐션):
- 기본 점수/그래프, 스트릭, 고정 루틴, 측정 신뢰도 안내

유료 후보 (개인 데이터 기반 = 대체 불가):
1. **루틴 효과 리포트** (3절의 케어×다음날 점수) — "당신에게 실제로 효과 있는 루틴"
2. **주간 AI 리포트 + AI 코치 멘트** (4절 LLM) — 체감 가장 큼
3. **비대칭/진짜미소 심화 분석** (2절) — 무료는 종합 점수만, 유료는 세부 지표
4. **수면×붓기 연동 인사이트** (HealthKit) — 연동형 프리미엄

## 6. 프라이버시 유의사항

- 얼굴 수치는 생체 유래 데이터 — 현행 "온디바이스 온리" 원칙 유지가 심사·신뢰 양면에서 유리
- LLM 리포트 도입 시: 원본 블렌드셰이프가 아닌 **요약 통계만** 서버 전송, 전송 항목을 설정 화면에 명시
- 생리주기·캘린더는 별도 옵트인 + 목적 설명 필수. 캘린더는 일정 "개수"만 사용
- 데이터 내보내기/삭제 기능을 초기에 넣어두면 이후 규제 대응 비용 절감

## 7. 요약

- 현재 체크인 1회당 **약 200개 수치**(52 스냅샷 + 15지표×3통계 + 메타)가 쌓이는 구조 완성. 활용은 아직 scoreDelta 1개뿐
- 가장 값싸고 효과 큰 다음 단계: **§2의 룰 기반 코칭 4종**(비대칭·진짜미소·긴장도·신뢰도) + **§3의 루틴 효과 검증**
- 그 데이터가 2~4주 쌓이면 **AI 리포트**(§4 LLM)가 자연스럽게 구독 기능으로 연결됨
