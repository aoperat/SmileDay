# 실시간 확인 세션 그래프와 비율 설계

- 날짜: 2026-07-30
- 상태: 구현됨 (2026-07-31 개정 — §6 스냅샷 철회)
- 상위 설계: `2026-07-29-live-smile-monitor-design.md` (이 문서가 §8·§11·§13·§14를 개정한다)
- 관련 설계: `2026-07-29-smile-frequency-window-reminders-design.md`

## 0. 개정 이력

### 2026-07-31 개정 — 스냅샷 전면 철회

**§6(스냅샷), §7의 사진 관련 항목, §9의 `claimSnapshotSlot()`, §10의 사진 메모리 예산, §12의 사진 검증 항목, §13의 문구 변경은 모두 무효다.** 그래프와 비율만 남는다.

이유는 상위 설계 `2026-07-29-live-smile-monitor-design.md`의 6차 개정에 적었다. 요약하면 — 이 앱의 대상은 평소 잘 웃지 않는 사람이므로 사진 격자는 평균적으로 "안 웃는 자기 얼굴"의 격자가 되고, 그건 판정하지 않겠다는 이 제품의 전제와 부딪힌다. 사진 없이도 **언제**는 띠가, **얼마나**는 비율이 말한다.

이 문서의 §2에서 "사진별 미소 여부 색 표시"를 버린 근거가 그대로 사진 자체에도 적용된다는 것이 뒤늦게 분명해진 셈이다.

따라 사라진 것: `LiveSmileSessionRecorder`의 스냅샷 슬롯 전부(`snapshotInterval`·`snapshotGrace`·`maxSnapshots`·`claimSnapshotSlot()`·`firstJudgeableAt`), `LiveSmileMonitorViewModel.snapshotRequestCount`, `ARKitLiveSmileMonitor.snapshotJPEGData()`, 요약 화면의 사진 스트립. `ARFrame.capturedImage`를 읽는 코드는 앱 전체에 남아 있지 않다.

## 1. 목적

실시간 확인 모드가 끝났을 때, 그 세션 동안 어떻게 웃었는지를 **그래프 하나와 비율 하나**로 보여준다.

해결하려는 문제는 두 가지다.

**(1) 지금 알림 타이머는 인식 품질에 흔들린다.** 프레임 간격을 합산하는 방식이라 얼굴을 놓치면 멈추는데, 잠깐 끊긴 것과 자리를 비운 것을 구분하지 못한다. 1초 단위로 기록해두면 끊김이 한 칸으로 남고, 그 칸을 "안 웃음"이 아니라 "모름"으로 적을 수 있다.

**(2) 세션이 끝나면 아무것도 남지 않는다.** 지금은 단계 미터가 실시간으로만 움직이고, 20분을 쓰고 나도 그 20분이 어땠는지 알 수 없다.

## 2. 무엇을 만들지 않는지

브레인스토밍에서 다음을 명시적으로 버렸다. 되살리려면 근거가 새로 있어야 한다.

| 버린 것 | 이유 |
|---|---|
| 1분/5분/10분/1시간 고정 창 | 세션 전체가 곧 창이다. 창을 미리 정하면 짧은 세션에서 큰 창이 계속 비고, 1시간 창은 발열이 먼저 한계에 닿는다 |
| 발생 횟수("4번") | 비율이 중심이 되면서 군더더기가 됐다. 함께 사라진 것: 연속 2초 최소 길이, 끊김 이어붙임, 지속 시간에서 이어붙인 칸 제외 |
| 기기 저장 | 세션 한정으로 두면 저장 위치·보존 기간·삭제 UI·개인정보 신고가 전부 불필요해진다 |
| 사진별 미소 여부 색 표시 | 사진 한 장마다 판정을 붙이는 일이다. 60장 중 50장이 회색이면 "한 시간 동안 안 웃은 나"를 격자로 보게 된다 |

## 3. 저장하지 않는다

**세션 한정이다.** 요약 화면을 닫으면 타임라인과 사진이 모두 메모리에서 사라진다.

- SwiftData와 UserDefaults에 샘플·비율·사진·세션 시간을 넣지 않는다.
- 날짜별 비교, 어제와의 대조, 앱을 닫고 다시 보기는 범위에 없다.
- `SmileMoment` 완료 횟수에 반영하지 않는다. 실시간 확인을 켠 것과 5초 미소를 완료한 것은 다른 행동이다.
- 네트워크 전송을 추가하지 않는다.

사용자 환경설정(알림 간격 등)은 예외다. 이미 `UserDefaults`에 있고 측정값이 아니다.

## 4. 기록 규칙

### 4.1 무엇을 미소로 보는가

**단계가 `starting` 이상** — 편한 표정 대비 신호 `0.10` 이상이다.

새 기준을 만들지 않았다. 알림이 이미 "`resting`이면 안 웃는 중"으로 판정하므로 같은 선을 쓴다. 기준이 두 개면 알림과 기록이 어긋난다.

### 4.2 세 가지 상태

```swift
public enum LiveSmileObservation: Equatable, Sendable {
    case smiling      // 단계 starting 이상
    case notSmiling   // 단계 resting
    case unknown      // 판정 불가
}
```

`unknown`이 되는 경우: 얼굴 없음, 시선이 `40°` 초과, 밝기 `300 lux` 미만, 보정 중, 그 1초에 프레임이 오지 않음.

### 4.3 1초 칸을 다수결로 접는다

틱마다 한 번 읽지 않는다. 그 1초의 **모든 프레임을 세서** 확정한다.

```
관측 프레임 0개                                  → unknown
판정 가능 프레임(smiling+notSmiling) < 관측의 절반 → unknown
그 외                                            → smiling vs notSmiling 다수
```

절반을 프레임 개수가 아니라 **비율**로 잡는다. ARKit이 항상 60fps를 주지 않으므로 30fps로 떨어져도 규칙이 그대로 성립해야 한다.

다수결을 쓰는 이유: 틱 샘플링은 59개 프레임을 버리고 마침 그 순간 튄 값이 1초 전체를 대표하게 만든다. 목적이 인식 오차를 걸러내는 것인데 정반대가 된다.

### 4.4 단계는 화면과 같은 값을 쓴다

EMA 평활(α 0.2)과 hysteresis를 **거친 뒤**의 단계를 기록한다. 미터가 미소를 보여줬는데 기록은 안 웃음이면 사용자가 납득하지 못한다.

화면 표시에 걸린 초당 10회 상한은 기록에 적용하지 않는다. 그것은 UI 갱신 제한이지 측정 제한이 아니다.

### 4.5 타이머를 쓰지 않는다

프레임이 도착할 때 "지금 몇 번째 초 칸인가"를 계산하고, **건너뛴 칸을 `unknown`으로 채운다.**

30초간 프레임이 오지 않으면 다음 프레임에서 30칸이 `unknown`으로 메워진다. 별도 처리 없이 "그 시간은 모른다"가 정확히 표현되고, 주입한 `now()`로 전부 테스트된다.

종료 시 마지막 부분 칸을 확정하고, **마지막 프레임 이후 종료까지의 시간도 `unknown`으로 채운다.** 이 끝머리를 빼면 `unknownRatio`의 분모가 줄어 세션이 실제보다 믿을 만해 보인다 — 과신을 막으려고 둔 신호가 거꾸로 작동한다. 종료를 누르려면 사용자가 있어야 하니 짧다고 단정할 수도 없다. 고개를 돌려 인식이 끊긴 뒤 한참 있다 누를 수 있다.

## 5. 비율

### 5.1 분모는 판정 가능한 시간이다

```
미소 비율 = smiling / (smiling + notSmiling)
```

`unknown`은 분모에서 **뺀다.** "카메라가 나를 본 동안, 그중 얼마나 웃고 있었나"다.

전체 실행 시간을 분모로 쓰지 않는 이유는 이 앱이 지켜온 원칙과 같다 — **모르는 것을 나쁜 것으로 적지 않는다.** 얼굴이 안 보인 9분을 "안 웃은 시간"으로 세면 자리를 비운 시간이 낮은 숫자로 돌아오고, 사용자는 자기 표정을 탓한다. 알림 타이머가 끊긴 구간을 세지 않는 것도 같은 이유였다.

### 5.2 분모가 작아진 것을 숨기지 않는다

분모에서 뺐으므로 **`unknown` 비율을 반드시 함께 보여준다.** 40%만 인식된 세션의 30%가 전부 인식된 세션의 30%처럼 읽히면 안 된다.

낮은 신뢰로 판정하는 조건(초기값, 실기기에서 조정):

- 판정 가능 시간 `60초` 미만
- 또는 `unknown` 비율 `50%` 초과

이때 비율은 보여주되 "인식된 시간이 짧아 이 숫자는 참고만 해주세요"를 함께 띄운다.

### 5.3 판정 가능 시간이 0이면 비율이 없다

보정만 하다 종료한 경우가 있다. `smilingRatio`를 `Double?`로 두고 이때 `nil`을 반환한다 — 0으로 나누는 경로를 타입으로 막는다. 화면은 "측정된 시간이 없어요"를 보여준다.

## 6. 스냅샷

- 주기는 **1분에 1장.** 측정 주기(1초)와 분리한다. 신호 1초 기록은 사실상 무료지만 사진은 메모리를 쓴다.
- 슬롯이 열리는 시점은 **측정 시작(보정 종료) 직후와 그 이후 매 분 경계**다. 10분 측정이면 최대 11장이다. 시작 직후 한 장을 두는 이유는 그 세션의 편한 표정이 어땠는지가 나중에 비율을 읽을 때 기준이 되기 때문이다.
- 분 경계 순간을 그대로 집지 않는다. **경계 이후 첫 판정 가능 프레임**을 쓴다. 경계를 그대로 집으면 눈을 감았거나 얼굴이 없는 사진이 남는다.
- 경계 후 `5초` 안에 쓸 프레임이 없으면 **그 분은 건너뛴다.**
- `240×320`으로 축소한다. 원본 해상도로 60장을 들면 메모리가 무의미하게 커진다.
- 상한 `120장`(2시간). 넘으면 사진만 중단하고 타임라인은 계속 쌓는다.
- **미소 여부로 색을 칠하지 않는다.** 사진은 사진으로만 둔다.

### 6.1 획득 경로

`ARFrame.capturedImage`를 축소 변환한다. `ARSCNView.snapshot()`은 프리뷰 뷰가 있을 때만 동작하고, 프리뷰 기본값이 꺼짐이므로 기본 상태에서 사진이 한 장도 남지 않는다.

1분에 1회라 픽셀 버퍼 변환 비용은 무시할 수준이다. 상위 설계 §8의 "`capturedImage`를 직접 읽어 변환하지 않는다"를 이 문서가 개정한다. **저장·전송 금지 조항은 그대로다.**

셔터음은 나지 않는다. `AVCapturePhotoOutput`으로 사진을 촬영할 때만 iOS가 소리를 강제하는데, 여기서는 이미 돌고 있는 세션의 프레임을 읽을 뿐이다.

## 7. 표시 시점

- **측정 중**에는 띠가 오른쪽으로 채워지는 것만 보여준다. 비율 숫자도, 경과 시간도 띄우지 않는다.
- **종료를 누른 뒤** 요약 화면에서 측정 시간과 비율을 보여준다.

띠는 1초에 한 칸씩 붙기만 하므로 지난 개정에서 없앤 0–100 숫자처럼 흔들리지 않는다. 동시에 재는 값을 실시간으로 들이대지 않으므로 자기를 계속 채점하게 만들 위험도 낮다. 기록이 쌓이고 있다는 사실은 자연스럽게 드러난다.

측정 중에 경과 시간을 넣지 않기로 했다. 그래서 **측정 중 띠에는 눈금이 없고, 3분인지 30분인지 화면만 보고는 알 수 없다.** 이건 알고 받아들인 대가다 — 측정 화면을 조용하게 두는 쪽을 택했다. 나중에 눈금이 필요해 보여도 되돌리기 전에 이 결정을 먼저 확인한다.

### 요약 헤더의 측정 시간

"측정 시간"으로 읽힐 수 있는 값이 셋이다. 헤드라인은 **`totalSeconds`** 하나로 정한다.

| 후보 | 값 | 쓰임 |
|---|---|---|
| 화면을 열어둔 시간 | 보정·대기 포함 | 쓰지 않는다 |
| **측정한 시간** | `totalSeconds` = 타임라인 길이 | **요약 헤더** |
| 판정 가능한 시간 | `usableSeconds` | 큰 숫자로 두지 않는다. `unknown` 비율로 이미 드러난다 |

`totalSeconds`를 고른 이유는 그래프의 가로축이 곧 이 값이라서 띠와 숫자가 일치하기 때문이다. 다른 값을 헤더에 쓰면 "24분"이라고 적힌 화면에 14분 30초짜리 띠가 그려진다.

## 8. 아키텍처

`LiveSmileMonitorViewModel`이 271줄, `LiveSmileMonitorView`가 412줄이다. 여기에 더 넣지 않는다.

### CoachingKit

```swift
public struct LiveSmileSessionSummary: Equatable, Sendable {
    public let timeline: [LiveSmileObservation]
    public let smilingSeconds: Int
    public let notSmilingSeconds: Int
    public let unknownSeconds: Int

    public var totalSeconds: Int { timeline.count }
    public var usableSeconds: Int { smilingSeconds + notSmilingSeconds }
    /// 판정 가능 시간이 0이면 nil
    public var smilingRatio: Double?
    /// 세션 길이가 0이면 0. 여기서도 0으로 나누지 않는다.
    public var unknownRatio: Double
    public var isLowConfidence: Bool
}

public final class LiveSmileSessionRecorder {
    public init(now: @escaping () -> Date = Date.init)

    /// 프레임마다 부른다.
    public func observe(_ observation: LiveSmileObservation)
    /// 측정 중 그래프용. 확정된 칸만 들어 있다.
    public var timeline: [LiveSmileObservation] { get }
    /// 분당 최대 한 번 true. 판정 가능한 프레임이고 경계 후 5초 안일 때만.
    public func claimSnapshotSlot() -> Bool
    /// 마지막 부분 칸을 확정하고 집계한다.
    public func finish() -> LiveSmileSessionSummary
}
```

`claimSnapshotSlot()`을 "물어보기 + 표시하기" 두 단계로 나누지 않는다. 표시를 잊으면 매 프레임 사진을 찍는다.

### 앱 타깃

- `LiveSmileSessionSummaryView` — 그래프·비율·사진 스트립
- 사진 배열과 픽셀 버퍼 변환

**패키지는 이미지를 들지 않는다.** CoachingKit은 UIKit을 import하지 않는 규칙이 있다. 그래서 타임라인은 패키지가, 사진은 앱 타깃이 갖는다. 스냅샷 타이밍만 패키지가 알려준다.

### 데이터 흐름

```
ARKit 프레임
  → LiveSmileMonitorViewModel: 품질 판정 → 평활 → 단계 → LiveSmileObservation
  → recorder.observe(observation)
       └ 초 칸이 넘어가면 다수결로 확정, 건너뛴 칸은 unknown
  → recorder.claimSnapshotSlot() 이 true면 앱이 capturedImage를 축소해 배열에 추가
  → 종료 → recorder.finish() → 요약 화면 → 닫으면 전부 해제
```

## 9. 예외 처리

| 상황 | 처리 |
|---|---|
| 판정 가능 시간 0초 | 비율 `nil`. "측정된 시간이 없어요" |
| 판정 가능 시간 60초 미만 | 비율 표시 + 낮은 신뢰 안내 |
| `unknown` 50% 초과 | 같은 안내 |
| 권한 거부·미지원 기기 | 측정 전 실패라 기록이 없다. 요약 화면을 띄우지 않는다 |
| 세션 실패·인터럽션 | 기록된 칸이 있으면 요약을 보여준다. 없으면(측정 시작 전 실패) 실패 화면 |
| 사진 상한 도달 | 사진만 중단, 타임라인 계속 |
| 백그라운드로 나감 | 세션이 멈춘다. 기록된 칸이 있으면 복귀 시 요약을 보여준다. 없으면 재시작 화면 |

## 10. 메모리

| | 단위 | 1시간 |
|---|---|---|
| 타임라인 | 초당 1바이트 수준 | 약 3.6KB |
| 사진 | 240×320 JPEG 약 25KB | 최대 3MB (120장 상한) |

## 11. 테스트

`LiveSmileSessionRecorder`는 전부 순수 로직이므로 패키지 테스트가 붙는다. 주입한 `now()`로 시간을 옮기고 실제 시계에 의존하지 않는다.

- 다수결 경계 — 판정 가능 프레임이 정확히 절반일 때
- 관측 프레임이 0개인 칸이 `unknown`
- 프레임이 30초 끊긴 뒤 30칸이 `unknown`으로 채워짐
- 비율 분모가 판정 가능 시간이고 `unknown`이 빠짐
- 판정 가능 시간 0 → `smilingRatio`가 `nil`
- 세션 길이 0 → `unknownRatio`가 `0` (0으로 나누지 않음)
- 낮은 신뢰 판정 경계 (60초, 50%)
- 첫 스냅샷 슬롯이 측정 시작 직후에 열림
- `claimSnapshotSlot()`이 분당 한 번만 true
- 경계 후 5초 안에 판정 가능 프레임이 없으면 그 분을 건너뜀
- 사진 상한 도달 후 더 true를 내지 않음
- `finish()`가 마지막 부분 칸을 포함시킴

이미지 변환과 요약 화면은 앱 타깃이라 테스트가 없다. 빌드로 검증한다.

## 12. 고쳐야 할 사용자 문구

사진을 집기 시작하므로 지금 문구 하나가 거짓이 된다.

| 위치 | 지금 | 조치 |
|---|---|---|
| 설정 화면 데이터 섹션 | "사진과 영상은 **찍지도**, 저장하지도 않아요" | **수정 필수.** 집지만 저장하지 않는다는 뜻으로 |
| 실시간 확인 시작 전 안내 | 사진 언급 없음 | 분당 1장 집고 닫으면 사라진다는 항목 추가 |
| 측정 중 배지 | "영상과 측정값은 저장하지 않아요" | 유지 — 여전히 사실 |
| `NSCameraUsageDescription` | "저장하거나 전송하지 않습니다" | 유지 — 여전히 사실 |

"표시하지 않는다"와 "저장하지 않는다"를 지난 개정에서 분리했다. 이번에는 **"집지 않는다"와 "저장하지 않는다"를 분리한다.** 절대 조항으로 남는 것은 저장·전송 금지뿐이다.

### AGENTS.md 가드레일

루트 `AGENTS.md`의 "Optional Live Mode Guardrails"에 사진 촬영 금지가 **절대 조항으로** 적혀 있다.

앞의 절반이 더 이상 사실이 아니다. 이 문장을 그대로 두면 다음에 이 코드를 만지는 사람이 스냅샷 기능을 규칙 위반으로 보고 지운다. 절대 조항을 **저장·전송 금지로 좁히고**, 촬영은 "세션 한정 · 분당 1장 · 내보내기 경로 없음"이라는 조건부 허용으로 바꾼다.

## 14. 범위 제외

- 고정 창(1분/5분/10분/1시간)
- 발생 횟수
- 기기 저장, 날짜별 비교, 앱 재실행 후 다시 보기
- 사진별 미소 여부 표시
- 사진 내보내기·공유·촬영 버튼
- 측정 중 비율 숫자 표시
- 단계 4종을 색 농담으로 구분하는 타임라인 (초기에는 3상태만)
- 얼굴 대칭·감정·인상 평가

## 15. 완료 기준

- 1초 칸이 그 1초의 프레임 다수결로 확정되고, 프레임이 끊긴 구간이 `unknown`으로 채워진다.
- 비율 분모가 판정 가능한 시간이고, `unknown` 비율이 화면에 함께 나온다.
- 판정 가능 시간이 0이면 비율 대신 안내가 나온다.
- 측정 중에는 띠만 자라고, 비율과 경과 시간은 종료 후에 나온다.
- 요약 헤더에 측정 시간(`totalSeconds`)이 나오고, 그 값이 그래프 가로축과 일치한다.
- 스냅샷이 분당 1장, 판정 가능한 프레임에서만 잡히고 색 판정이 붙지 않는다.
- 요약 화면을 닫으면 타임라인과 사진이 메모리에서 사라진다.
- SwiftData와 UserDefaults에 측정값이 추가되지 않는다.
- 설정 화면의 "찍지도 않아요" 문구가 사실에 맞게 수정된다.
- `LiveSmileSessionRecorder` 테스트와 `CoachingKit` 전체 테스트가 통과한다.
- iOS 17 앱 빌드가 통과한다.
- TrueDepth 실기기에서 셔터음이 나지 않고, 사진이 얼굴을 담고 있고, 장시간 사용 시 메모리가 상한 안에 머무는 것을 확인한다.
