# 월간 미소 기록 화면 설계

- 날짜: 2026-08-04
- 상태: 승인됨
- 배경: `SmileMoment`는 완료 시각을 계속 저장하지만 현재 UI는 오늘과 최근 7일만 보여준다. 마케팅 목업은 월간 기록 화면을 약속하고 있으며, 사용자가 장기 기록의 효용을 직접 확인할 화면이 필요하다.

## 1. 목표

- 홈의 최근 7일 카드에서 월간 기록 화면으로 이동한다.
- 월별 날짜마다 완료 횟수를 동일한 시각 강도로 보여준다.
- 월간 총 완료 횟수와 한 번 이상 웃어본 날의 수를 보여준다.
- 날짜를 선택하면 그날의 완료 횟수를 확인할 수 있다.

## 2. 제품 원칙

- 얼굴 사진·영상·실시간 센서값은 기록 화면에 들어오지 않는다.
- 미소 크기, 점수, 등급, 전월 대비, 목표 달성률을 표시하지 않는다.
- 0회인 날은 빈 날일 뿐 실패로 표현하지 않는다.
- 연속 기록과 기록이 끊겼다는 표현을 사용하지 않는다.
- 기본 기록 확인은 무료 핵심 가치로 둔다.

## 3. 데이터와 로직

기존 `SmileMoment`만 사용하며 새 SwiftData 모델이나 마이그레이션을 추가하지 않는다.

- `SmileMomentRepository.monthlyCounts(containing:calendar:)`는 해당 월의 모든 날짜를 오래된 순서로 반환하고 기록이 없는 날을 0회로 채운다.
- `SmileHistoryViewModel`은 표시 월, 날짜별 횟수, 월간 합계, 활동일 수, 선택 날짜를 관리한다.
- 이전 달은 제한 없이 이동할 수 있다. 다음 달 이동은 현재 달까지만 허용한다.
- 현재 달을 열면 오늘을 기본 선택한다. 다른 달로 이동하면 선택을 비운다.

## 4. 화면 구조

- 내비게이션 제목: `기록`
- 월 이동 헤더: 이전/다음 버튼과 `yyyy년 M월`
- 요약 카드: `이번 달 미소`, `웃어본 날`
- 일~토 7열 달력: 날짜와 횟수
- 선택 날짜 카드: `M월 d일`, `N번`

활동일은 주조색과 테두리로 표시하지만 횟수에 따라 색을 진하게 만들지 않는다. 날짜와 횟수 텍스트가 정보의 본체다.

## 5. 내비게이션

5탭 구조는 추가하지 않는다. 현재 `NavigationStack`을 유지하고 홈의 `최근 7일` 카드 전체를 버튼으로 만들어 기록 화면을 push한다.

## 6. 완료 기준

- 월 경계와 빈 날짜 채우기 로직이 패키지 테스트로 검증된다.
- 현재 달 이후로 이동할 수 없다.
- 홈에서 기록 화면에 진입하고 뒤로 돌아올 수 있다.
- 월간 합계·활동일·선택일 횟수가 저장 데이터와 일치한다.
- 기록이 없는 달도 중립적인 빈 상태로 정상 표시된다.
- `swift test`와 iOS simulator 앱 빌드가 통과한다.
